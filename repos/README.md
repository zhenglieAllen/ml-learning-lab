# repos — 第三方源码阅读笔记

**不复制完整仓库**。只保存你阅读源码产生的结论、调用链和验证记录。

## 目录结构

```text
repos/<repo-name>/
├── README.md       # 仓库地图 + 调用链 + 验证结论（模板见 LEARNING_PLAN.md §9）
├── architecture.md # 结构说明与调用链图
├── callchain.md    # 本次追踪的执行路径
├── notes/          # 分模块笔记
└── experiments/    # 最小复现实验与测试
```

上游仓库本身用 git clone 到仓库外的临时目录，或作为 submodule 记录 commit。

## 阅读原则

1. **从 README、安装配置、入口命令、测试、核心模块开始**，不要在全仓库里漫无目的翻。
2. **一次只追踪一条执行路径**。从一个入口进去，跟到输出出来。
3. **记录 commit / tag**，避免上游变化让结论无法复现。
4. **不要把猜测写成架构事实**。区分「我确认的」和「我推测的」。
5. **每次阅读都要产出一个可验证的问题**：某个张量形状、参数默认值、数据流、边界条件 —— 然后写测试或最小复现实验来回答它。

## 必答清单

- 输入从哪里进入？经过哪些函数 / 类？数据结构如何变化？输出从哪里产生？
- 错误处理和边界条件是什么？
- 依赖哪些第三方库？版本要求？
- 哪些地方的设计我觉得可以改进？能提交什么测试 / 文档 / 代码改进？
