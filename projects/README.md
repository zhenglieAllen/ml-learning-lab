# projects — 阶段性综合项目

把一个阶段或一轮学习整合成一个**可运行、可评估、可复现**的小项目。项目是学习成果的对外形态，也是阶段验收的依据。

## 目录结构

```text
projects/<project-name>/
├── README.md        # 问题、基线、方案、运行方式、结果、局限、复现步骤
├── requirements.txt
├── src/             # 核心代码
├── tests/           # 测试
├── results/         # 结果表、图表、演示产物
└── NOTES.md         # 设计取舍与踩坑记录
```

## 项目必须包含

1. **明确问题** —— 要解决什么任务，一句话能说清
2. **基线** —— 至少一个简单基线作为对照
3. **实验** —— 变量、指标、结果
4. **测试** —— 能跑通
5. **结果** —— 图表或数值
6. **局限性** —— 这个项目能说明什么、**不能**说明什么
7. **复现步骤** —— 别人（或三个月后的你）能照着跑起来

## 综合项目的最低要求

- 项目能在记录的环境下运行
- 能解释每个主要模块的作用
- 能指出实验结论的**证据**与**边界**
- 仓库中有其他人可执行的说明

## 与 experiments 的区别

- `experiments/` —— 为验证某个假设而做的一次性或对照实验
- `projects/` —— 面向完整交付的整合产物，代码质量要求更高

一个项目可以引用多个实验的结果，但项目自身要有独立入口。
