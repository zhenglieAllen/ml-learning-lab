# from_scratch/backpropagation — 手写反向传播

**交付周**：第 6 周（反向传播）

**这是整个基础阶段最关键的一环**，不通过不进入下一阶段。

## 要解决的问题

用计算图理解复合函数，逐节点应用链式法则，区分**局部梯度**和**传回的梯度**，并实现一个可被数值验证的手写反向传播。

## 必须自己回答的问题

- 局部导数是什么？传回梯度是什么？两者相乘得到什么？
- 为什么链式法则在计算图上就是「从输出往输入逐节点乘起来」？
- `dL/dw = dL/dy * dy/dw` 中每一项对应计算图上的哪个节点？
- 梯度累积（accumulation）是怎么回事？ microbatching 时为什么需要累加？
- 手写反向传播最容易错在哪一步？

## 流程要求（严格按序）

1. **手算**：在 `NOTES.md` 中，对一个极小的计算图（例如 `L = (a*b + c)^2` 或一个 2 层 MLP）完整写出前向数值、反向每一步的局部导数和传回梯度。
2. **编码**：在 `src/` 中实现计算图或手写 backward，与手算结果对照。
3. **梯度检查**：用有限差分验证每个参数，相对误差 < 1e-5。
4. **失败案例**：故意制造一个错误实现（梯度少乘一项、忘记累积、顺序反了），记录它表现为哪种错误现象。

## 交付物

- `NOTES.md` —— 手算笔记 + 形状标注
- `src/` —— 实现
- `tests/` —— 梯度检查（关键）
- `README.md` —— 结论、失败案例、常见错误

## 常见错误

- **忘记链式法则中的乘积**：把传回梯度直接当成本层梯度用
- **符号搞反**：梯度传回方向弄反，表现为 loss 上升
- **就地修改**：backward 中直接改写前向保存的中间值，导致第二次 backward 结果错误
- **梯度未清零**：每轮累加旧梯度（→ `pytorch_lab/autograd/` 会专门对照这一点）
- **广播维度错**：`X.T @ grad` 与 `grad @ X.T` 混淆
